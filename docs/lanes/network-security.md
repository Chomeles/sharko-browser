## 1. Mission and owned paths
Make Sharko's network behave and protect like Chrome's: the same wire identity (TLS, HTTP/2, header sets), the web's security rules enforced where the bytes flow (CORS, SameSite, referrer, CSP, mixed content, HSTS, CORP/ORB, cache partitioning), and a process design that survives a compromised renderer (network-service authorization, OS sandbox, site isolation). A bug is yours when a request goes out or is accepted differently from Chromium, when a security policy is missing, or when one process can do what only another may.
- Owned: `crates/netstack/**` (`core.rs` client build, `fetch.rs` pipeline, `headers.rs`, `cookies.rs`, `cache/{mod,policy,disk}.rs`, `alt_svc.rs`, `schemes.rs`, `service.rs`, `wire.rs`, `provider.rs`, `websocket.rs`, `error.rs`, `tests/`), `crates/common/src/{protocol,ipc}.rs` (shared), process spawning in `crates/browser/src/lib.rs` and `crates/launcher` (shared with stability), new policy logic (CORS safelist, referrer policy, SameSite, HSTS store, CSP wrapper) as modules or a small crate, `docs/adr/` (TLS/bot walls, CSP, sandbox), `tools/repros/network-security/`.
- Shared with the web-apis lane (claim one id together): `netstack/src/{fetch,headers,cookies,websocket}.rs`, `natives/misc.rs` `n_fetch`, `modules.rs` `start_fetch`, JS `40_webapi.js`. They own the Headers/Request/Response/fetch/XHR/EventSource/streams surface, you own what the network process enforces (CORS is in both briefs: you do netstack, they do the JS side, `tools/repros/web-apis/cors.html` is the shared acceptance page).
- Not yours: Chrome-identical default headers (a rust-lane agent is on `headers.rs`: `git log -20 -- crates/netstack` first and build on it), EventSource/streams JS, blob: module import, `cookieStore`, service-worker API (web-apis), `<base href>`, layout, the UI of cert/download pages (shell-ui; you supply the data).

**1. Web pages can read and run local files (S, low risk; security, do first).**
- Evidence (repro `file-scheme.html`, verified today): from an http page `fetch('file:///etc/hostname')` and sync XHR return the file, `<script src="file:///...">` executes it, `<link rel=stylesheet href=file:...>` loads; Chromium: TypeError / error events ("URL scheme "file" is not supported", "Not allowed to load local resource"). Any site can read files whose path it can guess (`C:\Windows\win.ini`, hosts, `/etc/passwd`, the profile's `cookies.json` once the user name is known) and send them out.
- Mechanism: `NetworkCore::fetch` (`core.rs:109`) dispatches by scheme only, `schemes::file` (`schemes.rs:69`) serves any path to any requester, `NetRequest` (`protocol.rs:55`) carries no requester, `n_fetch` (`misc.rs:242`) and `BlitzNetProvider::fetch` (`provider.rs:60`) forward whatever the page asks, and `FromRenderer::OpenUrl` (`browser/src/lib.rs:553`) navigates to any scheme.
- Fix: a document may load `file:` only when its own URL is `file:` (or the browser UI asked). Reject in the JS layer (fetch, XHR, import, importScripts) before sending, drop in `CountingNetProvider::fetch` (`engine/src/host.rs:83`, knows the document via `doc_id`, incl. iframes), and in netstack as defence in depth (interim `NetRequest.allow_local`, later the initiator of item 3); the browser refuses renderer `OpenUrl` to `file:`/`javascript:` unless the tab is `file:`. Tests: the repro, a netstack test through a fake renderer connection, a JS-layer test. Refs: Blink `third_party/blink/renderer/core/fetch/fetch_manager.cc`, `content/browser/renderer_host/navigation_request.cc`, SV `net/fetch/methods.rs` (scheme fetch).

**3. Request context in `NetRequest` and Fetch-metadata parity (M, low risk; foundation of 4-9).**
- Evidence (repro `request-metadata.html`): a classic `<script src>` goes out as `Sec-Fetch-Dest: empty` + `Mode: cors` + `Origin` (Chrome: script / no-cors / no Origin); module scripts as no-cors without Origin and with the document as Referer even for nested imports (Chrome: cors + Origin, Referer = importing module; `<link rel=modulepreload>` is never fetched); `fetch(u,{mode:'no-cors'})` as cors + Origin; css/img/font without `Referer` and `Sec-Fetch-Site`; iframes as dest empty (Chrome: iframe/navigate/`Upgrade-Insecure-Requests`, Referer).
- Mechanism: `NetRequest` has `destination`, `referrer`, `credentials: bool` only; `headers.rs::apply_defaults` (`:144`) derives Origin (`:176`) and Sec-Fetch-* (`:199`) from method/destination/referrer; `n_fetch` maps every non-navigate mode to `Destination::Fetch` (`misc.rs:264`, NATIVE_API.md:162 calls `mode` informational); `modules.rs:355 start_fetch` uses `Destination::Script` for all; `BlitzNetProvider::fetch` ignores `doc_id` (`provider.rs:60`) and vendor `stamped_request` (`blitz-dom/src/net.rs:29`, `iframe.rs:142`) sets no referrer.
- Fix: append to `NetRequest` (new fields at the END, mirror them in `wire.rs`, whose byte-equality tests fail otherwise) `mode` (navigate|same-origin|no-cors|cors|websocket), `initiator_origin`, `top_level_site`, `credentials` (omit|same-origin|include), `referrer_policy`, `integrity`; track the redirect-tainted origin in `Hop::redirect` (`fetch.rs:71`, `Origin: null`; WPT redirect-origin, 12 fail); fill the fields in `n_fetch`/`n_fetch_sync`, `modules.rs`, the bootstrap script fetch (`crossorigin`) and `CountingNetProvider` (from `doc_id`); Referer and Sec-Fetch-* derive from them. Leave the default header set to the other agent. Refs: LB `Fetch/Infrastructure/HTTP/Requests.{h,cpp}`, SV `shared/net/request.rs`, CR `services/network/public/cpp/cors/cors.cc`. WPT: fetch/metadata (checkout), fetch/api/redirect.

**4. CORS enforced in the network stack (L, medium risk).**
- Evidence: `fetch/api/cors` 32.8%, `/cors` 35%, ~20 xhr preflight files. A cross-origin response without `Access-Control-Allow-Origin` is handed to script (n-tv.de and europa.eu then `JSON.parse` a geo/WAF HTML page: `Unexpected token '<'`; Chromium: `TypeError: Failed to fetch`), custom-header/PUT/JSON requests go out without OPTIONS, module and `crossorigin` scripts run without ACAO. Acceptance page: `tools/repros/web-apis/cors.html`.
- Mechanism: `40_webapi.js:2492-2560` only taints and filters exposed headers; netstack adds Origin (`headers.rs:176`) but never checks the answer; no preflight, no preflight cache.
- Fix (spec HTTP fetch, per hop in `fetch.rs`): CORS-safelist check; preflight (OPTIONS with `Access-Control-Request-Method/Headers`, 2xx only, no redirects, Max-Age default 5 s and cap 7200 s as in CR `preflight_result.cc`, cache key origin+url+credentials, partitioned by top-level site); CORS check of the final response and of each redirect hop (ACAO exact origin or `*` without credentials, ACAC, `null`, wildcard headers/methods only without credentials); on failure a network error plus the console line `Access to fetch at ... has been blocked by CORS policy: ...`; the same for `<script crossorigin>`, modules, fonts, `<img crossorigin>`; exempt data:, blob:, same-origin (file: is item 1). Follow-ups: ORB (fetch/orb, corb), `mode:'same-origin'` redirects, `fetch('about:blank')` must reject, SRI `integrity` (WPT 5 fail, SV `net/subresource_integrity.rs`). Refs: LB `Fetching.cpp` (http_fetch, CORS check) + `Infrastructure/HTTP/CORS.cpp`, CR `services/network/cors/*`, SV `net/fetch/{methods,cors_cache}.rs`, `http_loader.rs`.

**5. Referrer policy (M, low risk).**
- Evidence (repro `referrer-policy.html`, 6 of 9 cases fail): `referrer`/`referrerPolicy` of fetch, `<meta name=referrer>`, the `Referrer-Policy` header and `referrerpolicy=`/`rel=noreferrer` (reflected in `30_html.js:148`, unused) are ignored; WPT `redirect-referrer-override` 71/128 failing, `redirect-referrer` 14/32, `policies` 5/16, `basic/referrer` 2/6; the referrer-policy directory has 1398 tests (not run).

Refs: LB `ReferrerPolicy/AbstractOperations.cpp`, CR `net/url_request/referrer_policy.cc`, GK `dom/security/ReferrerInfo.cpp`.

**6. Cookies: SameSite, third-party context, Partitioned, limits (M-L, medium risk).**
- Evidence: `cookies.rs:17` says SameSite is not enforced; repro `samesite-cookies.html` (a cross-site iframe's fetch sends Strict, Lax and default cookies, Chromium sends none); no `Partitioned` (CHIPS), no 400-day expiry cap (CR `canonical_cookie.cc:286`), no limits (180 per registrable domain, 3300 total, CR `cookie_monster.cc:229-231`); the persisted jar is clear text in `<profile>/cookies.json`.
- Fix: needs `initiator_origin`/`top_level_site` from item 3 on requests and on `GetCookies`/`SetCookie` (`protocol.rs:132`, document.cookie in third-party frames). RFC 6265bis: Lax by default, Strict, `SameSite=None` needs Secure, schemeful same-site (`headers.rs::same_site` already is), Lax+POST 2-minute exception, Set-Cookie ignored in cross-site responses when SameSite forbids it. Then a `PartitionKey{session, top_level_site}` shared with item 11 (README roadmap "sessions per tab" = several jars keyed by session id: design once). Third-party cookie blocking is an owner setting (Chrome still allows 3PC; `docs/PROCESS.md` section 11), DPAPI (`CryptProtectData`) for the persisted file. Refs: CR `net/cookies/{cookie_util,canonical_cookie,cookie_monster}.cc`, LB `LibHTTP/Cookie/*`, SV `net/{cookie,cookie_storage}.rs`, GK `netwerk/cookie/*`. WPT: cookies (89, checkout).

**7. Network-service authorization and IPC hardening (S-M, low risk; security review).**
- Findings: (a) every renderer receives the one network endpoint and token in `ToRenderer::Init` (`protocol.rs:264`) and the service trusts what it says: `GetCookies`/`SetCookie` for any URL (`service.rs:342-346`), any `Origin`/`Referer`/`credentials` on `Fetch` with the raw response returned (no ORB), `WsOpen{origin}` (`protocol.rs:138`), `file:` reads (item 1), and `Shutdown` (`service.rs:347`; "browser only" is not enforced): a compromised renderer steals every session. (b) `--ipc=name#token` is on the command line (`ipc.rs:422 spawn_child`, visible to other local processes; on Linux abstract sockets are reachable by every local user), Windows pipes get the default DACL and `try_overwrite(true)` (`ipc.rs:52-75`). (c) The browser follows `OpenUrl` to any scheme (`lib.rs:553`). (d) A tab keeps one renderer across navigations, all frames share it (item 14).
- Fix in steps: the browser registers a capability per renderer connection (assigned origin/site, no `Shutdown`, no `file:`) and the service rejects out-of-lock requests, cookie URLs and WS origins (CR `services/network/restricted_cookie_manager.cc`, `url_loader.cc` initiator origin lock); pass pre-connected pipe handles to children (`PROC_THREAD_ATTRIBUTE_HANDLE_LIST` / inherited fds) instead of name+token on the command line, or set an explicit DACL and `FILE_FLAG_FIRST_PIPE_INSTANCE` (`interprocess` 2.4.4 has `security_descriptor` options on Windows); `OpenUrl` scheme filter; `SHARKO_EXTRA_CA` only in non-release builds. Test: `crates/netstack/tests/ipc.rs` with a second, unprivileged connection.

**8. Response-header policies: CSP, X-Frame-Options/frame-ancestors, nosniff, CORP/COEP/COOP, ORB (L, medium risk).**

- Fix in order: X-Frame-Options + `frame-ancestors` (S) and `X-Content-Type-Options: nosniff` for script/style (S); CSP on the `content-security-policy` crate: header and `<meta>` at commit, a `CspList` per document, checks at script execution (inline, nonce, hash, `strict-dynamic`, eval through a V8 callback), fetch/XHR/WS (`connect-src`), img/style/font/frame/form-action/base-uri, `sandbox`, report-only and the `securitypolicyviolation` event; CORP + ORB in the network service; COEP/COOP-lite (`crossOriginIsolated`, `window.opener` nulling; a real browsing-context-group swap needs item 14). Refs: LB `ContentSecurityPolicy/*`, CR `services/network/public/cpp/{content_security_policy/content_security_policy.cc, orb/orb_impl.cc, cross_origin_resource_policy.cc}`, GK `nsCSPContext.cpp`, `FramingChecker.cpp`. WPT: content-security-policy 904, fetch/{nosniff,orb,corb,cross-origin-resource-policy}, x-frame-options, html/cross-origin-*.

**9. Secure transport policy: HSTS, mixed content, upgrade-insecure-requests, HTTPS-first (M).**
- Evidence: no `Strict-Transport-Security` handling (grep); an https page loads `http:` scripts, css, iframes and XHR (Chrome blocks them and auto-upgrades images/media); `Upgrade-Insecure-Requests: 1` is sent but nothing follows it (upgrade-insecure-requests: 206 WPT tests).
- Fix: an HSTS store in netstack (dynamic, includeSubDomains, `max-age=0` removal, persisted, plus Chromium's preload list `net/http/transport_security_state_static.json`) applied before each request and redirect hop; mixed content per spec (blockable vs optionally blockable; needs initiator and top-level from item 3; also `ws:` from https); HTTPS-first navigation with fallback and warning (`https-upgrades`). Refs: SV `net/hsts.rs` (+ tests), CR `net/http/transport_security_state.cc`, `mixed_content_checker.cc`, LB `MixedContent/AbstractOperations.cpp`, GK `nsMixedContentBlocker.cpp`, `nsSiteSecurityService.cpp`.

**10. Certificate errors and TLS UX (M).** Evidence: every TLS failure becomes the generic `pages/error.html` with `net::ERR_CERT_*` (`error.rs:126`, `renderer.rs:1759`): no interstitial, no per-host exception, HSTS hosts are not special-cased (Linux sweep: oddspark, 1drv). Fix: interstitial (error class, "Advanced" -> "Proceed (unsafe)" per session and cert SHA-256, never for HSTS hosts) fed by netstack (`NetError` gets a certificate-chain summary); an exception list consulted by a custom `ServerCertVerifier` (or the BoringSSL callback after item 2); revocation/CT policy as an ADR; keep OS trust (rustls-platform-verifier). CR `net/cert/cert_verify_proc.cc`, `net/ssl/ssl_config_service.cc`.

**11. HTTP cache: partition key and RFC 9111 correctness (M).** Evidence: `primary_key(url, credentials)` (`cache/mod.rs:56`) shares one cache across all sites (a resource cached for site A is a hit for site B: tracking and timing side channel); `request-cache-only-if-cached` 4/14; WPT `fetch/http-cache` (16) and `stale-while-revalidate` (7) not run. Fix: key = url + `PartitionKey{session, top_level_site, frame_site}` (item 6), review Vary/Authorization/`private`, bump the disk format version, then run the two WPT directories. CR `net/base/network_isolation_key.cc`, `net/http/http_cache_transaction.cc`, `http_response_headers.cc`; SV `net/http_cache.rs`; LB `LibHTTP/Cache/*`.

**12. Streaming bodies and downloads (L, medium risk).**
- Evidence: `FromNetwork::Response(NetResponse)` carries the whole body (`protocol.rs:147`, `fetch.rs:153 read_body` collects it, `MAX_BODY_BYTES`): no SSE/EventSource (WPT 0/98, web-apis repro `eventsource.html`), no `response.body` streams, no progressive media, big files sit in RAM; non-renderable types show the "unsupported" page (`renderer.rs:825 DocKind::Other`): no Content-Disposition, `<a download>` or download manager (GOALS Stage 1 UI basic).
- Fix: new variants at the END of `FromNetwork`/`ToNetwork` (postcard encodes the index): `ResponseStart{status,headers}`, `Chunk{id,bytes}`, `End`/`Error`, backpressure by an ack window (web-apis builds streams and EventSource on it); downloads: `Content-Disposition` + `filename*` parsing, save under a temp name, dangerous-type warning, Windows Mark-of-the-Web (`Zone.Identifier` stream: ZoneId=3, HostUrl, ReferrerUrl) so SmartScreen/Office see the origin; UI in shell-ui. CR `net/http/http_content_disposition.cc`, `net/base/filename_util.cc`, `components/download/internal/common/download_item_impl.cc`, `chrome/browser/download/download_target_determiner.cc`.

**13. Windows OS sandbox for renderers and the network process (L, design first, high risk).**
- Today: SECURITY.md admits there is none. A renderer runs with the user's rights, reads and writes the profile directly (`crates/script/src/storage.rs`), and the network process reads any file for `file:`.
- Design note (ADR) first. Renderers need only IPC (inherited pipe handles, item 7), system fonts (read `C:\Windows\Fonts` and the font registry key: verify with a Low-IL token) and no GPU (they paint display lists); move localStorage/profile access and the crash-dump writer to the browser process. Steps: job object (`ActiveProcessLimit=1`, `KILL_ON_JOB_CLOSE`, UI limits); restricted token (`DISABLE_MAX_PRIVILEGE`, deny-only SIDs) at Low integrity (`S-1-16-4096`); process mitigations via `PROC_THREAD_ATTRIBUTE_MITIGATION_POLICY` (strict handle checks, extension points, image-load restrictions; Win32k lockdown only after checking the renderer never touches GDI/user32; no ACG because of V8's JIT); AppContainer (`CreateAppContainerProfile`, no capabilities) as phase 2. Use `windows-sys` directly (Chromium's C++ `sandbox/win` is BSD-3 but large; Firefox ships a copy: GK `security/sandbox/win/src/sandboxbroker/sandboxBroker.cpp`). Verify with a `--selftest-sandbox` step in `windows-e2e.yml` (renderer must fail CreateFile in the user profile, CreateProcess, opening a foreign pipe, outbound sockets). CR `sandbox/policy/win/sandbox_win.cc`, `sandbox/win/src/*`.

**14. Site isolation roadmap (design M, then L-XL).** Today one renderer and one V8 isolate serve every frame of a tab and survive cross-site navigations (`ToRenderer::Navigate` replaces the document in the same process). Steps: (S1) origin lock (item 7); (S2) a fresh renderer for every cross-site top-level navigation (`Browser::open` and `spawn_renderer(id, epoch, ..)` in `lib.rs`: small); (S3) COOP process swap; (S4) out-of-process iframes: nested display lists composed in the browser process, hit testing and `postMessage` routed through the browser (the JS layer already reaches other-origin frames through `N.framePost`), one realm per process instead of one isolate per page; write the ADR before code. CR `content/browser/{site_instance_impl,process_lock,renderer_host/render_process_host_impl}.cc`.

**15. Enterprise network settings: HTTP authentication, proxy, DoH (M each, later).** xhr `send-authentication-*` (~19 fail) show no 401 handling: no Basic/Digest/NTLM/Negotiate (Windows SSPI), no prompt, no `user:pw@` URL credentials, no credential cache; proxies come from reqwest `system-proxy` (env and registry, no PAC/WPAD, no proxy auth); DNS is the system resolver (no DoH). CR `net/http/{http_auth_controller,http_auth_handler_ntlm,http_auth_sspi_win}.cc`, `net/dns/{host_resolver_manager,context_host_resolver}.cc`, `net/dns/public/doh_provider_entry.cc`, GK `netwerk/dns/TRR*.cpp`.

## 4. How to work
- Build (long first build: V8, Stylo, aws-lc-sys; Linux needs `clang lld libfontconfig1-dev libxkbcommon-dev libwayland-dev`; `tools/dev-setup.sh` automates the rest once merged): `cargo build --profile profiling -p browser-core -p browser-launcher -j N` (`.cargo/config.toml` sets `[build] jobs = 2`, always pass `-j`). Binary `target/profiling/browser`; one `target/` only (~8 GB free per machine, no copies); the JS layer is embedded at build time. Windows CI builds with MSVC (static CRT); `tools/build-windows.sh` cross-builds from Linux.
- Tests: `cargo test --profile profiling -p netstack` (local hyper/h2/h3/TLS servers in `crates/netstack/tests/support`; `real_sites.rs` is `#[ignore]`d; `wire.rs` pins byte equality with `protocol.rs`), `-p common -p script`, `node crates/script/js/test/run.js`, `tools/check.sh --rust` (its cargo step skips netstack: run it yourself). New wire fields go at the END of structs and enums.
- Repros: `node tools/repros/network-security/run.js [--chromium] [--verbose] [PAGE.html]` starts `serve.py` on localhost:18941/18942 and 127.0.0.1:18943 (same origin, same site, cross site; Sharko needs `NO_PROXY=localhost,127.0.0.1`, Playwright `PLAYWRIGHT_DISABLE_FORCED_CHROMIUM_PROXIED_LOOPBACK=1` behind the sandbox proxy; the runner sets both). Remove a page from `xfail.txt` when its fix lands. Fingerprint: `target/profiling/browser --headless --eval='document.body.textContent' https://tls.peet.ws/api/all` vs the same in Playwright Chromium; the sandbox proxy is a MITM, so the final judge is a Windows CI run.
- WPT: checkout and hosts per `tools/wpt/README.md` (`./wpt serve --no-h2`), `node tools/wpt/run.js --batch --jobs=3 fetch/api cors xhr`; committed rows for cookies/CSP/referrer/mixed-content without `--batch`; `--update <dir>` and commit `expected.json` with the fix; never two WPT runs at once on 4 cores. Flaky: keepalive, `abort/general`, `xhr/open-url-multi-window*`, `access-control-sandboxed-iframe-*`, anything timing-based under load.
- Real sites: `node tools/sitediff/run.js https://www.aldi-sued.de/ https://www.ndtv.com/ https://www.idealo.de/ https://www.microsoft.com/de-de/` (needs Playwright). Pitfalls: `HTTPS_PROXY` is a MITM (403s, bot walls, random blocks; HTTP/3 is off behind a proxy, `fetch.rs:559`), never unset it; Chromium may itself be walled (site skipped, not scored); wall pages flip per request and per egress IP (ing.de, aldi): repeat before believing a change; no site names in `crates/`.

## 5. Done / quality bar
A good commit: one behaviour; a test that fails before (netstack integration test, `crates/script/tests/`, JS-layer test) and the repro page out of `xfail.txt`; the WPT directories it touches with no UNEXPECTED and `expected.json` updated in the same commit; numbers before/after in the message. Security changes (items 1, 7, 8, 13, 14) get a fresh-context verifier per `docs/PROCESS.md`; TLS, CSP and sandbox get an ADR in `docs/adr/`. `cargo fmt`, no new warnings, no site names, no model names in files. Vendor changes carry `// PATCH:` and an entry in `vendor/README.md` (avoid them: stamp requests in `engine/src/host.rs` instead of `blitz-dom/src/net.rs`). JS-layer or native changes are documented in `crates/script/js/README.md` ("Known gaps") and `NATIVE_API.md`, with the mock in `test/mock_native.js`. Ported code carries `// Ported from <project> <path> (<licence>)` and a `THIRD_PARTY_NOTICES.md` entry (Servo files stay MPL-2.0). Commit: `<summary> [skip ci]` as in `git log -5` (`docs/PROCESS.md` section 10 wins once its CI change is in your checkout: no `[skip ci]`, add `Fixes:`/`Changelog:`); body = mechanism, rule followed, tests, sites/WPT before -> after; trailers `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` and `Claude-Session: <your session URL>`.

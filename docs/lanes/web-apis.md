## 1. Mission and owned paths
Make every platform API a page calls besides the DOM behave like Chromium: networking (fetch, XHR, CORS, streams, WebSocket, EventSource), workers and messaging, storage (IndexedDB, CacheStorage, Web Storage, cookies), Blob/File/URL/encoding, WebCrypto, performance, observers, and the small API surface scripts feature-detect (locale, credentials, scheduler, navigation). A bug is yours when a script sees a missing or wrong API result, a wrong rejection, or a wrong header/body while the DOM and layout are right.
Owned: JS layer `crates/script/js/40_webapi.js` (sections by line: structuredClone/messaging 172, URL 979, TextEncoder 1323, Blob/File 1480, streams 1766, Headers 1991, Request/Response 2117, fetch 2390, XHR 2559, WebSocket 2976, Worker 3101, crypto 3317, performance 3786, navigator 4242, Location/History 4629, Storage 4813, Intersection/ResizeObserver 4917) and `45_indexeddb.js`; a new layer file is picked up by `build.rs` by file name (e.g. `42_streams.js`, `46_cache_sw.js`; also add it to `LAYER_FILES` in `test/harness.js:10` and the file table in `README.md`); natives `crates/script/src/{storage,blob,modules,compress}.rs` and `natives/{misc,crypto}.rs`; network stack `crates/netstack/src/{fetch,headers,client,service,wire,websocket,cookies}.rs` + `crates/common/src/protocol.rs` (NetRequest, NetResponse, WsEvent), shared with the network-security lane (TLS, HSTS, CSP are theirs); tests `crates/script/js/test/`, `crates/script/tests/`, `crates/netstack/tests/`; `tools/repros/web-apis/`; the rows of my directories in `tools/wpt/expected.json`.
Not yours: DOM, events and the script execution model (`10/20/30/90_*.js`, dom-events lane), Shadow DOM, layout/CSS, audio/video/WebGL/canvas/WebCodecs/WebRTC (graphics-media: `AudioContext`, `MediaSource`, `VideoDecoder` stay absent; a silent `OfflineAudioContext` is theirs if heise.de's fingerprint script matters), site isolation. Running elsewhere, do not duplicate: the Chrome-identical headers lane (talk to it before touching the header set in `headers.rs`; item 1 only adds `mode`/`Origin` logic), base href, css-prefs, container queries.

## 3. Backlog (highest value first; S < 1 day, M a few days, L a week or more)
**1. Enforce the same-origin policy for fetch and XHR: CORS check, preflight, Sec-Fetch-Mode (M + M, medium risk, security).**
  Evidence: `cors.html`: a cross-origin `fetch`/XHR with no matching `Access-Control-Allow-Origin` resolves with the body (Chromium: TypeError / `error` event), `credentials:'include'` with `ACAO: *` or without `ACAC` resolves, a custom header / PUT / JSON POST goes out with no `OPTIONS` (Chromium sends one and never sends the real request when it fails), `mode:'no-cors'` carries `Sec-Fetch-Mode: cors`. Today any page can read other sites' responses, cookies included. WPT fetch/api: 863 failing subtests (188 `Should have rejected` in 24 tests, ~62 `Preflight request has been made`, 91 forbidden/no-cors header tests, ~85 redirect-referrer, 18 Origin-after-redirect); xhr 484 (access-control denials, preflight statuses); cors 145/414 (35.0%).
  Cause: `40_webapi.js:2513-2540` (fetch) and `:2649-2700` (XHR) label a cross-origin response `cors` without the CORS check (Fetch "CORS check"); nothing implements the CORS-preflight fetch or its cache (`grep -ri preflight crates` is empty); `NetRequest` (`common/src/protocol.rs:55`) carries no mode or origin, so `headers.rs:209` derives `sec-fetch-mode` from the destination and `Hop::redirect` (`netstack/src/fetch.rs:71`) cannot set Origin `null` after a cross-origin redirect; `is_safe_method` (`headers.rs:139`) treats OPTIONS/TRACE as safe, the spec skips Origin only for GET/HEAD. The dossier `malformed-json` (Origin missing on cross-origin GET) is fixed; its three follow-ups (no preflight, no ACAO enforcement, `sec-fetch-mode`) are this item.
  Fix: (1) JS layer: the CORS check on the final response (ACAO `*` only without credentials, else the exact serialized origin; ACAC `true` for `include`), a preflight before non-safelisted requests: `OPTIONS` through `L.startNativeFetch` with `Access-Control-Request-Method` and sorted lowercase `-Headers`, no credentials, 2xx + ACAO/ACAM/ACAH check, cache keyed (origin, url, credentials) with `Max-Age` (default 5 s, cap 600), repeat for redirects; `sanitize()` (`headers.rs:43`) already passes `Access-Control-Request-*`. (2) Rust: `mode`, `origin`, `redirect_tainted` in `NetRequest`/`WireRequest`/`Hop` for Origin and `Sec-Fetch-Mode` (coordinate with the chrome-headers lane). Others: Servo `components/net/http_loader.rs` (`cors_preflight_fetch`) + `components/net/fetch/cors_cache.rs`; Ladybird `Libraries/LibWeb/Fetch/Fetching/Fetching.cpp` + `Fetch/Infrastructure/HTTP/CORS.cpp`; Blink `services/network/cors/preflight_controller.cc`, `cors_url_loader.cc`; Gecko `netwerk/protocol/http/nsCORSListenerProxy.cpp`. Sites that only work because CORS is not enforced will fail like in Chromium: that is the point.

## 4. How to work
- Build: Rust stable, Python 3, `clang lld libfontconfig1-dev` on Linux (`tools/dev-setup.sh` automates the rest once merged). `cargo build --profile profiling -p browser-core -p browser-launcher` (long on a fresh machine: V8, Stylo; `.cargo/config.toml` has `jobs = 2`, pass `-j N`); binary `target/profiling/browser`. One `target/` only (~8 GB free per machine, no copies). JS-layer edits are embedded at build time (`crates/script/build.rs`): rebuild before running the binary; the Node harness needs no build.
- Fast loop: `node crates/script/js/test/run.js [name]` (5 s; `mock_native.js` is a JS `__native` with a fake clock, routed fetch responses and frame natives: extend it with every native you add), `cargo test --profile profiling -p script -p netstack -p common` (netstack has real local servers in `crates/netstack/tests/support`: put CORS/streaming tests there), `tools/check.sh --rust`.
- Repros: `node tools/repros/web-apis/run.js [--chromium] [PAGE.html]` (starts `serve.js` on :18931/:18932 = two origins; endpoints `/api/cors`, `/api/log`, `/api/slow`, `/api/sse`, `/api/wasm-add` are documented in its header; pages follow the contract `window.__repro = {issue, expected, actual, pass}` from `repro.js`; remove a page from `xfail.txt` when its fix lands). Sharko needs `NO_PROXY=localhost,127.0.0.1` (run.js sets it); Playwright needs `PLAYWRIGHT_DISABLE_FORCED_CHROMIUM_PROXIED_LOOPBACK=1` in this sandbox or the proxy answers 405. Sharko parses the whole document before running scripts (`document.body` exists in a head script, later elements are visible): repro pages wait for `load`.
- WPT: checkout, hosts entries and `./wpt serve --no-h2` per `tools/wpt/README.md`. `node tools/wpt/run.js --batch --jobs=3 fetch/api xhr streams workers`; committed expectations: run the directory without `--batch` (needed for IndexedDB, webstorage, FileAPI: storage carries over between batch tests) and with `--update`; `--workers` for the `.any.worker.html` variants of the same tests; `node tools/wpt/summarize.js results.json` (from `--json=`) ranks failure messages (used for the clusters below). Never run two WPT runs in parallel on 4 cores, timeouts flip.
- Real sites: `node tools/sitediff/run.js --out=/tmp/sd URL...` (Playwright + Chromium; `--compare-only`, `--refresh`), read `out/<site>/diff.json` and `sharko.log`. `node tools/api-inventory/compare.js` for the global surface.
- Pitfalls: the sandbox proxy is a MITM (403 for some hosts, bot walls, `HTTPS_PROXY` must not be unset); a worker realm runs on the page's thread (a busy loop hangs the page until the 10 s watchdog, `Atomics.wait` cannot work); one V8 isolate serves all frames of a page, each frame has its own layer instance (so layer-level `Map`s are per frame); `caches` is listed in `WORKER_SHARED` but does not exist; do not touch `expected.json` rows of directories you did not run.

## 5. Done / quality bar
A good commit: one behaviour; a test that fails before (JS-layer test in `crates/script/js/test/tests/`, netstack test, or `crates/script/tests/*.rs`) and, for a page-visible behaviour, the repro page moved out of `xfail.txt`; the WPT directories it touches with no UNEXPECTED and `expected.json` regenerated for the new passes in the same commit; numbers before/after in the message. Root cause, not per-site: no site names in `crates/`.

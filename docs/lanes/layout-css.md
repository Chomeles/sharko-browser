## 1. Mission and owned paths
Make pages lay out and paint like Chromium: fewer wrong boxes on real sites (tools/sitediff), more CSS web-platform-tests passing (testharness now, reftests once item 1 exists).
A bug is yours when a box is sized, placed, styled or painted wrongly, or the CSS side of the CSSOM is wrong.
Owned: `vendor/blitz-dom/src/` (`layout/{construct,inline,table,abspos,replaced,list,damage}.rs`, `resolve.rs`, `stylo.rs`, `stylo_to_kurbo.rs`, `stylo_to_parley.rs`, `scrolling.rs`,
`viewport_overflow.rs`, `document.rs` prefs, `node/`), `vendor/blitz-dom/assets/default.css` (UA sheet), `vendor/blitz-paint/`, `vendor/taffy/src/compute/`, `vendor/parley/` (line breaking),
`vendor/stylo_taffy/`, `crates/engine/{src/raster.rs,tests/}`, `tools/wpt/`, `tools/repros/layout-css/`. Shared with the JS lane (small, coordinated edits): CSSOM in `crates/script/js/20_dom.js`
(StyleSheet, getComputedStyle) and `matchMedia` in `40_webapi.js`. Not yours: Shadow DOM, netstack, script execution.
Running elsewhere, do not duplicate: css-prefs (alt-text `content`, media features), container queries, base href, Chrome headers, the airbnb/coursera/bing/pons layout hunt, kleinanzeigen, and the
differential miners `lane/diffmine-layout` and `lane/diffmine-css` (`tools/diffmine/`, reports in `docs/compat/`: use their clusters as input once merged, do not rebuild them).
`git log --oneline -20 master` before touching the prefs in `document.rs` or `stylo.rs`.

## 4. How to work
- Build: Rust stable, Python 3, `clang lld libfontconfig1-dev` on Linux. `cargo build --profile profiling -p browser-core -p browser-launcher` (long on a fresh machine: V8 and Stylo; `.cargo/config.toml` sets `jobs = 2`, pass `-j N`). One `target/` only (~8 GB free per machine, no copies).
  Run: `target/profiling/browser --headless --window-size=800x600 --screenshot=out.png URL` (`--eval=JS`, `--dump-dom`, `--console`).
- Tests: `cargo test --profile profiling -p blitz-dom -p engine -p script` (model layout test: `crates/engine/tests/viewport_overflow.rs`: HTML in, paint, rasterize, assert pixels; unit tests live in `vendor/blitz-dom/src` and `vendor/taffy/src`), `node crates/script/js/test/run.js` when the JS layer changes, `tools/check.sh --rust`.
- WPT: checkout, hosts entries and `./wpt serve --no-h2` per `tools/wpt/README.md` (`tools/dev-setup.sh` automates it once merged). Quick loop `node tools/wpt/run.js --batch --jobs=3 css/css-grid css/css-flexbox`; committed expectations: run the directory without `--batch`, with `--update`. Flaky by nature: animation/transition
  interpolation tests (css-position/animations, css-variables/variables-animation-math-functions flip ~10 subtests per run), keepalive, timeouts under load: re-run before believing an UNEXPECTED. `node tools/wpt/summarize.js results.json` ranks failure messages.

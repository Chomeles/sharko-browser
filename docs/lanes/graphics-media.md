- Evidence (`images.html`): AVIF and a palette-less GIF fail to decode, EXIF orientation is ignored (Chromium's `image-orientation: from-image` is the default: the rotated JPEG is 240x320; reftest `image-orientation-exif-png-3` fails), `image-set(a 1x, b 2x)` picks the last candidate at DPR 1 (3 image-set reftests fail). apple.com_de: 36/43 images "broken" in both sweeps (`data:image/gif;base64,R0lGODlhAQABAHAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==`). **12. Video/audio playback pipeline (L, high: decisions first, write an ADR before code).**
- Options: (A) Windows Media Foundation (`windows` crate: `IMFSourceReader` over our own byte stream with range requests; H.264/AAC/MP3 by OS decoders, so patent licences stay with the OS; DXVA hardware decode; VP9/AV1/HEVC/Opus depend on installed Store extensions; Windows only; Firefox does it: GK `dom/media/platforms/wmf/WMFDecoderModule.cpp`); (B) portable bundle: `symphonia` (pure Rust MP3/AAC-LC/FLAC/Vorbis/WAV, MP4/MKV/Ogg demux) + `dav1d` (AV1) + libvpx + libopus + openh264 only with Cisco's binary (licence): testable on Linux CI, no hardware decode, H.264 patent exposure; (C) FFmpeg LGPL dynamic (LB `LibMedia/FFmpeg/FFmpegVideoDecoder.cpp`, BL `media/filters/ffmpeg_demuxer.cc`; broadest, 30-70 MB, licence work); (D) GStreamer (`servo/media` `backends/gstreamer/player.rs`; heavy runtime, poor fit for one Windows zip).
- Recommendation (Firefox's split): MF for H.264/AAC/MP3 on Windows + bundled royalty-free decoders (dav1d, libvpx, libopus, symphonia) + own demuxers behind one `trait MediaBackend` in `crates/media`, so Linux CI tests the B path. Pipeline: demux -> decode -> A/V sync on the audio clock (cpal/WASAPI) -> frames. Frames must not travel as RGBA in the postcard display list (1080p = 8 MB): a shared-memory ring per video element (Windows file mapping) referenced from the display list (`VideoSurface{id, rect, fit}`), uploaded by the compositor (`write_texture`, YUV->RGB shader; the vello_cpu path converts on the CPU).
- Milestones: audio (mp3/wav/ogg) plays -> MP4/H.264 with sound and seeking on Windows -> VP9/AV1/WebM -> `MediaSource`/`SourceBuffer` (YouTube, Twitch, hls.js; BL `modules/mediasource/media_source.cc`, `media/filters/source_buffer_stream.cc`, LB `MediaSourceExtensions/*`) -> captions, `mediaCapabilities`, default controls UI (nothing draws controls today). Item 1 is its state machine. CI runners have no sound card and no GPU: null audio sink + frame hashes.
**13. WebGL (L, high) and WebGPU (after).**
- `getContext('webgl'|'webgl2')` is null and stays null until a REAL implementation exists. No fake contexts (the dossier's "plausible getParameter values" idea is rejected: scripts that get an object draw and read pixels back, scripts that get null degrade). `webgl.html` is the acceptance page.
- Options: (A) ANGLE (D3D11 backend on Windows; Chromium, Firefox and Ladybird use it, Ladybird's `vcpkg.json` lists `angle`): the `mozangle` crate (Servo's cargo-buildable ANGLE, `egl` feature on Windows, BSD-3) or prebuilt libEGL/libGLESv2; exact WebGL semantics and GLSL ES validation; v1 renders into an FBO in the renderer process and reads back (`glReadPixels`) into the canvas bitmap like the 2D path, zero-copy via DXGI shared handles later; (B) WebGL on wgpu (already in the tree for the compositor): needs GLSL ES -> WGSL and a GL state machine, large and inexact, rejected. Init failure -> null + `webglcontextcreationerror` (allowed by the spec).
- Deliver: spike (context, triangle, `readPixels`) -> WebGL1 + the extensions Chrome exposes -> WebGL2 -> `OffscreenCanvas` webgl (item 11) -> context loss events -> Khronos conformance subset as test target. WebGPU only after: `wgpu` 29 is in the tree, `deno_webgpu` (MIT, wgpu-core, v8 bindings) is the reference for the JS surface.
- Refs: LB `WebGL/{WebGLRenderingContextBase,WebGLRenderingContextImpl,WebGL2RenderingContext}.cpp`; BL `modules/webgl/webgl_rendering_context_base.cc`; SV `components/script/dom/webgl/webglrenderingcontext.rs`; GK `dom/canvas/WebGLContext.cpp`.
**14. Animated images (M, low).** `image` decodes frame 0 only: animated GIF/APNG/WebP stand still (`images.html` files; `net.rs` `ImageHandler::parse`). Decode all frames with the `AnimationDecoder` traits, keep frames + delays in the image resource, advance from the frame loop (`crates/engine/src/renderer.rs`: wake at the next frame time, pause when off screen), give canvas `drawImage` the current frame. Refs: LB `HTML/AnimatedBitmapDecodedImageData.cpp`; BL `platform/graphics/bitmap_image.cc`.
**15. Web Audio (L, after 12's audio output).** No `AudioContext`/`OfflineAudioContext` exists (honest today; heise's audio fingerprint throws `is not a constructor`; Cloudflare/DataDome fingerprint it). Graph engine on the pipeline's output: oscillator, gain, biquad, dynamics compressor, analyser, buffer source, `decodeAudioData` via the media decoders, deterministic `OfflineAudioContext.startRendering`, `AudioWorklet` last; `webaudio.html` is the acceptance page. Refs: LB `WebAudio/*`; BL `modules/webaudio/audio_context.cc`; SV `servo/media` `audio/context.rs`, `components/script/dom/audio/*`.
**Later (Stage 2/3, no design yet):** PDF viewer (a PDF shows "unsupported": `decode::classify` -> `DocKind::Other`, `crates/engine/src/renderer.rs:825`; options: pdfium via `pdfium-render` + pdfium-binaries, pure-Rust `hayro`, or PDF.js inside the engine, which also stresses canvas), printing (`window.print` is a no-op, no paged layout: start with print-to-PDF of the laid-out page), text rendering fidelity (hinting, gamma, LCD vs DirectWrite; colour emoji: vello has COLR support, unverified because Linux machines have no emoji font: measure on Windows CI screenshots first).

## 4. How to work
- Build: `cargo build --profile profiling -p browser-core -p browser-launcher` (target dir default `target/`; the first build on a fresh machine is long and takes most of the ~8 GB you have free: ONE `target/`, never copy it, one cargo at a time). Run: `target/profiling/browser --headless --profile=/tmp/p1 --window-size=1000x780 --screenshot=/tmp/x.png file://$PWD/tools/repros/graphics-media/paint-matrix.html` (also `--eval=EXPR`, `--wait-for=EXPR`, `--full-page`, `--console`, `--scale=2`); repro contract: `--wait-for=window.__repro --eval='JSON.stringify(window.__repro)'`. Behind the sandbox proxy set `SHARKO_EXTRA_CA=/root/.ccr/ca-bundle.crt` for https sites.
- Screenshots are drawn by vello_cpu. The window path (Vello on the GPU: `crates/shell`, vendored `anyrender_vello`) has no GPU on a cloud machine: make every paint feature work in `common::display_list::replay` on both backends, pin it with a CPU render test (pattern `crates/engine/tests/{svg_sprite,viewport_overflow}.rs`: HTML in, pixels out) and check the GPU path on the Windows CI run.
- Tests: `cargo test -j 3 --profile profiling -p script -p engine -p blitz-dom -p blitz-paint`; JS layer: `cd crates/script/js/test && npm install` once, then `node crates/script/js/test/run.js [filter]`; `tools/check.sh [--rust]`. WPT: `tools/dev-setup.sh` (checkout, hosts, `./wpt serve`; if it is not in the repo yet, follow `tools/wpt/README.md`), then add this lane's directories: `cd ../wpt && git sparse-checkout add css/css-images css/css-backgrounds css/css-masking css/css-transforms css/filter-effects css/geometry css/css-fonts css/css-text css/css-text-decor css/css-font-loading css/compositing css/css-shapes css/css-color css/css-ui css/css-image-animation css/reference svg html/canvas html/semantics/embedded-content webaudio media && git checkout` (~50 MB, blobs on demand).
- `node tools/wpt/run.js --batch --jobs=3 svg html/canvas` (`--json=F` then `node tools/wpt/summarize.js F` for failure clusters; a directory without entries in `tools/wpt/expected.json` needs `--update` once and its expectations committed). Reftests: `node tools/repros/layout-css/reftest-proto.js --wpt=../wpt --sample=60 --jobs=2 css/css-backgrounds` until layout-css lands `run.js --reftests`. Real sites: `node tools/sitediff/run.js https://www.computerbase.de/ https://www.apple.com/de/` (Playwright: `npm i -g playwright && npx playwright install chromium`). The Windows CI run is authoritative (Linux machines lack Arial, DirectWrite, Media Foundation and a GPU).
- Pitfalls: bot walls answer with challenge pages (check `document.title` before trusting a diff); WPT batch mode shares storage between tests (use per-process mode for a committed baseline); media/autoplay and `keepalive` tests are flaky and time out; on a 4-core machine two WPT runs plus cargo cause 15 s timeouts that are not regressions; headless has no audio device and no GPU: media, WebGL and audio tests need null sinks, offline contexts and software paths.

## 5. Done / quality bar
- Every fix ships a regression test: the repro page passes in Chromium and Sharko and leaves `xfail.txt`, and/or a Rust render test, a JS-layer test in `crates/script/js/test` (extend `mock_native.js` for new natives), a WPT flip (run the directory, `--update`, commit the smaller `expected.json`); the directory run has no UNEXPECTED. Painting is judged by reftests and screenshots, not by testharness counts.
- `vendor/blitz-*`, `vendor/anyrender_vello`, `vendor/stylo` changes carry `// PATCH: <why>` and an entry in `vendor/README.md`. JS-layer changes are documented in `crates/script/js/README.md` (drop the "Known gaps" entries you fix: canvas/media stubs, WebGL, OffscreenCanvas; keep the honesty rules of "Chrome consistency" true and update `test/tests/61_chrome_consistency.test.js`), every new `N.*` in `NATIVE_API.md`.
- Root cause, not per site: no site names in `crates/`; evidence is two unrelated sites, a WPT flip or a repro page. Read the reference path named in the item before designing (`docs/REFERENCE-MAP.md`: Ladybird BSD-2 and Blink BSD-3 may be ported with `// Ported from <project> <path> (<licence>)` and a `THIRD_PARTY_NOTICES.md` entry; Servo/Gecko files stay separate with their MPL header; no LGPL code). - Never fake an API: `getContext('webgl')` is null, `AudioContext` absent, `canPlayType` '' until the real thing decodes/renders.

Never push tags, no pull requests, no model names in files, no edits in another lane's files without a handoff note; keep `docs/status/graphics-media.md` to 12 lines (done id+sha+before>after, doing, blocked, next).

# Lane brief: shell-ui (browser application: window, tabs, omnibox, pages, Windows integration)

Rules win over this file: `docs/RULES.md`, `docs/PROCESS.md`. State of the repo when written: 2026-09-29 (Sharko 0.2.x, Windows is the only release platform).

## 1. Mission and owned paths

Turn the shell from "a tab strip, an address bar and back/forward" into a browser a person can use all day: history, bookmarks, downloads, find, context menus, settings, real error pages, session restore, Windows integration. Plus a UI test harness so shell states are checked by screenshots, because headless mode cannot show any of this UI.

Owned: `crates/shell/` (src/lib.rs 1418 lines winit App + paint, chrome.rs 468 tab strip/toolbar as a Blitz HTML doc, keys.rs 96 shortcuts), `crates/browser/` (lib.rs Browser + Tab + session history, update.rs signed updater, headless.rs), `crates/launcher/`, `crates/core/src/installer.rs` and the CLI in `crates/core/src/lib.rs`, `resources/ui/` (chrome.html/css, icons), `resources/pages/` (newtab, error, crash, unsupported), `resources/locales/{en,de}.json`, `tools/repros/shell-ui/`, new `.github/workflows/ui-shots.yml`. Shared (coordinate, keep edits small): `crates/common/src/protocol.rs` (IPC enums ToRenderer/FromRenderer), `crates/engine/src/renderer.rs` (page side of any new message), `crates/netstack` (downloads, error classes; owned by the network lane).

WPT barely covers this area (the shell is native UI), so the goals are feature and screenshot based, plus the few WPT directories that touch it.

Goal C: WPT `html/browsers/history` and `html/browsers/windows` fewer non-pass subtests, plus a first measured baseline for the not-yet-run directories below.

### What exists vs what is missing (read from the code, 2026-09-29)

Exists: winit window created hidden then cloaked/shown (DWM cloak on Windows, avoids white flash; lib.rs `mod win`); GPU compositor (vello/wgpu, `anyrender_vello`) with automatic CPU fallback (`vello_cpu`, forced by env `BROWSER_RENDERER=cpu`; there is no `--cpu` flag yet) and a GPU-init crash marker (`GPUCache/init-pending`); chrome = HTML doc rendered by Blitz (`Chrome::new/set_tabs/set_toolbar/handle_ui_event`, `data-action` attributes → `Action` enum: NewTab, SelectTab, CloseTab, Back, Forward, Reload, Stop, Go, RevertUrl, Home, ZoomIn/Out/Reset, Restart); tabs with title, spinner, close button, crashed class; sad-tab recovery (`TabCrashed` → `respawn_tab` with crash.html, max 3 per 30 s); omnibox with `fixup_input` (host heuristics, else DuckDuckGo search; hardcoded twice: chrome.rs:467 and resources/pages/newtab.html), lock/info icon, zoom indicator; per-tab zoom 25 to 500 %; shortcuts (keys.rs): Ctrl+T/W/L/R/Tab/Shift+Tab/PageUp/Down/1-9/+/-/0, Alt+Left/Right/Home, F4, F5, F6, F11, Alt+D, BrowserBack/Forward/Home keys, mouse back/forward buttons; own overlay scrollbar for the viewport; cursor mapping; IME plumbing to the page (Ime events → `InputEvent::Ime*`, `set_ime_allowed`); dark mode follows OS (`ThemeChanged` → viewport `dark`); high-DPI scale factor; fullscreen F11; session history per tab in `browser::Tab` (`history`, `HistoryEntry`, pushState aware); clipboard for the address bar (arboard); localization via `resources/locales/{en,de}.json` + `{{t.key}}` templates (`common::i18n`); pages: newtab (6 hardcoded tiles), error, crash, unsupported ("This file can't be displayed"); signed auto-update (`browser/src/update.rs`: manifest ed25519, sha256, background check 20 s after start then every 6 h, "Update ready – restart" pill, `--check-update`); per-user installer (`--install`/`--uninstall`: Start menu + desktop shortcut, HKCU uninstall key); launcher with versioned folders and rollback; portable mode (`portable` file).

Missing (grep finds nothing in crates/shell, browser, launcher, resources): persistent history (only per-tab session history), autocomplete/suggestions dropdown, bookmarks, downloads (any non-HTML type shows the "can't be displayed" page), file dialogs (`<input type=file>`), context menus (mouse button 2 goes straight to the page), find in page, print, drag and drop (no `DroppedFile`/`HoveredFile`, no tab dragging, no link drag), permission prompts, password manager/autofill, favicons (`.fav` is an empty div), pinned/duplicated/muted tabs, tab overflow, session restore (Ctrl+Shift+T, restore on start), reopen closed tab, settings pages (no about:settings, about:history, about:downloads, about:version), certificate error interstitial (rustls errors become the generic error page), offline page, incognito/per-tab profiles (README roadmap "sessions per tab": the network process has ONE cookie jar under `profile_dir`), popup blocker, alert/confirm/prompt UI (check: WPT `html/webappapis/user-prompts` has 3 failures), text selection copy in page (content clipboard: verify), accessibility (no AccessKit; note `vendor/blitz-dom` has an `accessibility` feature backed by the accesskit crate, unused), default-browser registration (installer writes only the uninstall key), single-instance forwarding (a second `browser.exe url` starts a second browser process with its own window), jump list, AppUserModelID/taskbar grouping, window icon (`with_window_icon` absent), per-monitor DPI manifest (verify), auto-update UX beyond the pill (no progress, no failure surface, no channel).

### S0 UI harness (do first, everything else is verified with it)
Evidence: no test in the repo renders the chrome; `crates/shell` has no tests; headless screenshots (`crates/engine/src/raster.rs`, `VelloCpuImageRenderer::render_to_vec`) show only the page.
Design: add `browser --ui-shot=<scenario>[,<scenario>...] --out=DIR [--size=1280x800] [--scale=1] [--dark]` in `crates/core/src/lib.rs`, implemented in a new `crates/shell/src/uishot.rs`. It builds `Chrome`, feeds it scripted `TabView`/`ToolbarView` states (`set_tabs`, `set_toolbar`, `set_update_ready`, focused address bar via `focus_url`, typed text via `set_url_text`), resolves it, and calls the existing nested `paint_all` (lib.rs:648, generic over `PaintScene`) on a `VelloCpuImageRenderer` (same as raster.rs), then `encode_png`. No window, no GPU, runs on Linux CI. Scenarios (15 minimum): empty-newtab, 1-tab-loading, 12-tabs-overflow, crashed-tab, address-focused-typing, https-lock, http-insecure, zoom-indicator, update-ready-pill, dark-newtab, hidpi-2x, error-page, crash-page, plus each new feature (menus, find bar, downloads bubble) as it lands. To show a page under the chrome without a renderer process, feed a `Frame` or render `resources/pages/*.html` through the engine's headless path into the content rect (see `Browser::new_tab` in single_process mode in crates/browser/src/lib.rs). Golden files: `tools/ui-shots/golden/*.png` (keep < 60 KB each; 1280x800 → downscale to 640x400 with nearest neighbour before saving), compare with a per-pixel tolerance script `tools/ui-shots/compare.js` (fail if > 0.5 % pixels differ by > 8/255; write a diff image). Update flag `--update`.
Real window on Windows CI: new workflow `.github/workflows/ui-shots.yml` (trigger: file `tools/ci/ui-shots.trigger` like windows-smoke.yml, and workflow_dispatch). Steps: build (reuse windows-smoke.yml build job), start `browser.exe --profile=%TEMP%\p https://example.com` with `BROWSER_RENDERER=cpu`, wait for the window, drive input with a small PowerShell/SendInput helper or with an env `SHARKO_UI_SCRIPT=file.json` (scripted actions: type, click chrome element by data-action, press key, wait, screenshot) handled inside the app so it does not depend on the desktop, and capture with an in-process framebuffer dump (`SHARKO_UI_DUMP=path.png` writes the last presented CPU frame). Expectation to verify in the first run: GitHub windows-latest runs jobs in an interactive desktop session (this is why headed Playwright/Selenium works there; default resolution is small, 1024x768, set with `Set-DisplayResolution` if needed); if `CopyFromScreen` returns black, use `PrintWindow(hwnd, PW_RENDERFULLCONTENT)` or rely on the in-process dump. Upload PNGs as artifacts. Reference: Servo `ports/servoshell/desktop/headed_window.rs` and `ports/servoshell/desktop/gui.rs` (egui shell, window/event glue); Chromium `chrome/browser/ui/views/frame/browser_view.cc` (pixel tests use `views::ViewsTestBase` + `ui/base/test`), no direct Ladybird equivalent (their UI is Qt/AppKit; `UI/Qt/BrowserWindow.cpp`).

Reference: Ladybird `Libraries/LibWebView/HistoryStore.cpp`; Chromium `components/history/core/browser/history_backend.cc`; Gecko `browser/components/places/content/places.js` (Places is the store: history+bookmarks in one DB). ### S9 Tabs: session restore, drag, pin, duplicate, favicons

## 4. How to work

Build (fresh machine: first build takes long, V8 + Stylo + vello; keep exactly one `target/` and ~8 GB free; do not copy it):
`cargo build --profile profiling -p browser-core -p browser-launcher` (binary `target/profiling/browser`). `CARGO_TARGET_DIR` default. Linux needs `clang lld libfontconfig1-dev`, Python 3.
Run the UI: only on a machine with a display: `target/profiling/browser about:newtab`; without display use the harness of S0 (`--ui-shot`). CPU compositor: `BROWSER_RENDERER=cpu`. Debug: `BROWSER_DEBUG_EVENTS=1` logs window events, `--verbose`, `--single-process` (renderer as thread), `--profile=DIR`, `--no-update`.
Tests: `cargo test --profile profiling -j 3 -p shell -p browser -p common` (add unit tests for stores, menus models, `fixup_input`, registry key tables); `node crates/script/js/test/run.js` when you touch the JS layer bridge; `tools/check.sh --rust` before pushing; WPT: `node tools/wpt/run.js --batch --jobs=3 html/browsers/history html/browsers/windows html/webappapis/user-prompts` (needs the WPT checkout `../wpt`, the hosts entries and `./wpt serve --no-h2`; `tools/dev-setup.sh` (being written by another session; if missing follow tools/wpt/README.md)). Compare pages with Chromium: `node tools/sitediff/run.js URL...` (needs Playwright + Chromium); it never shows the shell.
Repro pages: `tools/repros/shell-ui/` (`python3 tools/repros/shell-ui/serve.py` then open http://127.0.0.1:8765/<page>).
Pitfalls: the sandbox proxy adds noise (badssl.com, DuckDuckGo suggestions may be blocked; test with local servers); bot walls in sitediff are not shell bugs; WPT `keepalive` tests are flaky; a headless run never proves a shell change: show a screenshot. Windows is the only release platform: never use `#[cfg(unix)]`-only paths for a feature without the Windows implementation (Linux may stay a stub but must compile). Do not block the winit event loop (dialogs, file IO, network go to threads and return through `UserEvent`). Chrome height is a constant (`CHROME_HEIGHT`, chrome.rs:16) used for hit-testing and viewport size: overlays paint above content and do not change it. Untrusted page input must never reach `about:` privileged bridges. The shared IPC enums in `common::protocol` are also used by the renderer, the headless driver and WPT tooling: add variants, do not change existing ones.

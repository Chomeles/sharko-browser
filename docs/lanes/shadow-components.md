## 1. Mission and owned paths
Make Shadow DOM and custom elements behave like Chromium: a real shadow tree (light tree untouched, slot assignment, flat tree for style, layout, paint, events, focus) instead of today's emulation that moves nodes around; then complete custom-element reactions, form-associated elements and ElementInternals.
Web-component sites (otto.de, stern.de, MDN, Lit/Svelte hydration) and every Cloudflare Turnstile challenge depend on it.
- JS layer `crates/script/js/`: `20_dom.js` (shadow emulation L201-310, `preInsert`/`lightInsert` L858-890, foreign-node adoption L821-856, ShadowRoot L2634-2700, CE state and reactions L390-500 and L2738-2760, `setAttrCore` L985, CustomElementRegistry L4083-4175),
  `30_html.js` (HTMLSlotElement ~L1095, innerText ~L281, `attachInternals`/ElementInternals L613-700, forms/FACE L2810+), `10_events.js`, tests `test/tests/60_components.test.js`, `test/mock_native.js`, docs `NATIVE_API.md`, `README.md` ("Known gaps").
- Native: `crates/script/src/{dom,selector,events,html,forms}.rs`; `vendor/blitz-dom/src/{shadow_css.rs, document.rs (style_scope ~L1300, set_shadow_host L1324), stylo.rs (L276-300, 364-396, 577, 640-670, 874-880), layout/construct.rs, traversal.rs, node/}`; `crates/engine` (hit testing, focus). Repros: `tools/repros/shadow-components/`.

## 4. How to work
- Build (long first build on a fresh machine: V8, Stylo): `cargo build --profile profiling -p browser-core -p browser-launcher` -> `target/profiling/browser` + `libbrowser_core.so`. Keep ONE `target/` (about 8 GB free per machine; no copies, no second profile).
  `crates/script/build.rs` `include_str!`s the JS files, so every JS edit relinks a ~380 MB library: iterate with the mock harness, rebuild only to run WPT or pages. `tools/dev-setup.sh` (written by another lane) sets up WPT hosts and server.
- Tests: once `cd crates/script/js/test && NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt npm install`; then `node crates/script/js/test/run.js [name]` (5 s idle, ~50 s loaded; `80_perf` and the `70_indexeddb` bulk test fail on time only under load); `cargo test -j 3 --profile profiling --no-fail-fast -p script -p blitz-dom -p engine`; `tools/check.sh [--rust]`; fuzzer `node tools/fuzz/run.js --seeds=8` (extend it with attachShadow/slot operations for items 2-3).
- WPT: sparse checkout `../wpt` (`tools/wpt/README.md`), hosts (`./wpt make-hosts-file | sudo tee -a /etc/hosts`), `./wpt serve --no-h2` running.
  Iterate: `node tools/wpt/run.js --batch --jobs=3 shadow-dom custom-elements html/semantics/scripting-1/the-template-element dom/nodes dom/events dom/ranges`. One test: `--filter=gethtml --verbose <dir>`. Dump: `--json=out.json`, then `node tools/wpt/summarize.js out.json`.
  Confirm with a NON-batch run before `--update` (batch shares storage). `/shadow-dom` needs ~8 min at 1 job and TIMEOUT tests dominate: re-run a new TIMEOUT alone before believing it.
- Probes: `node tools/repros/shadow-components/compare.js [--verbose] [name]` (Sharko vs stored Chromium values, prints TOTAL); `--update-expected` regenerates them from real Chromium (Playwright). Pages define `window.__out()` and set `window.__done`.
- Sites: `node tools/sitediff/run.js https://www.otto.de/ https://www.stern.de/ https://developer.mozilla.org/en-US/docs/Web/HTML https://www.handelsblatt.com/` (Playwright + Chromium); run twice before believing a score. One page: `SHARKO_EXTRA_CA=/root/.ccr/ca-bundle.crt target/profiling/browser --headless --console --settle=3000 --eval='...' URL`.
- Pitfalls: the sandbox proxy blocks `brunhild.challenges.cloudflare.com`, so even Chromium cannot pass Cloudflare there. Local success = repro probes green, no `TypeError` from the Turnstile iframe, no POST `/cdn-cgi/challenge-platform/.../chl_api_m`; final proof only on the Windows CI sweep. The `NaN` console lines of Turnstile are its devtools trap, not errors.
  Bot walls, A/B tests and consent banners make single sitediff runs noisy. `expected.json` (5 MB) is edited by every lane: `--update` only your directories, rebase often, on conflict re-run `--update` on the merged file. New top-level state in the JS layer must obey the snapshot purity rules (`NATIVE_API.md` "Load-time purity").

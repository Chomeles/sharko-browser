Login/form flows, rich-text editors, ad/consent iframes and hydrating frameworks (Stage 1 of `docs/GOALS.md`) depend on it.

**4. iframe identity: initial about:blank document, `javascript:` and `srcdoc` frames (M, medium risk).**
- Evidence: `iframe-initial-document` 0/5: a script-created iframe reports the PARENT's URL (`location.href`, `document.URL`), readyState interactive, CSS1Compat, origin `same`; Chromium `about:blank`, complete, BackCompat, opaque origin. ## 4. How to work
- Build (long first build: V8, Stylo): `cargo build --profile profiling -p browser-core -p browser-launcher` -> `target/profiling/browser` + `libbrowser_core.so`. ONE `target/` (about 8 GB free per machine, no copies). `crates/script/build.rs` `include_str!`s the JS, so every JS edit relinks a ~380 MB library: iterate with the mock harness, rebuild only for WPT and pages. `tools/dev-setup.sh` (written by another lane) prepares WPT hosts and server.
- Tests: once `cd crates/script/js/test && NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt npm install`; `node crates/script/js/test/run.js [name]` (5 s idle; `80_perf`/`70_indexeddb` fail on time only under load); `cargo test -j 3 --profile profiling --no-fail-fast -p script -p blitz-dom -p engine`; `tools/check.sh [--rust]`; fuzzer `node tools/fuzz/run.js --seeds=8`.
- Probes: `node tools/repros/dom-events/compare.js [--verbose] [name]` (TOTAL line; `--update-expected NAME...` rewrites the Chromium values with Playwright; pages set `window.__done` and define `window.__out()`). Parser: `node tools/repros/dom-events/html5lib.js [--verbose] [--only=tests1.dat]` (needs `../wpt/html/syntax/parsing/resources`; all files take about 3 min).
- WPT: sparse checkout + hosts + `./wpt serve --no-h2` (`tools/wpt/README.md`), then `node tools/wpt/run.js --batch --jobs=3 dom html/dom html/webappapis html/semantics/forms html/browsers`; one test `--filter=NAME --verbose DIR`; `--json=out.json` then `node tools/wpt/summarize.js out.json`. Confirm with a NON-batch run before `--update` (batch shares storage). TIMEOUT tests dominate slow directories: re-run a new TIMEOUT alone; `keepalive` and scroll tests are flaky.
- Sites: `node tools/sitediff/run.js https://www.samsung.com/de/ https://www.bing.com/ https://www.stepstone.de/` (Playwright + Chromium; run twice). One page: `SHARKO_EXTRA_CA=/root/.ccr/ca-bundle.crt target/profiling/browser --headless --console --settle=3000 --eval='...' URL`; `--single-process` + `RUST_BACKTRACE=1` shows a renderer panic.
- Pitfalls: `--batch --settle=0` evaluates before the page finished (results shift by one URL): use `--wait-for='document.readyState==="complete"'`; the sandbox proxy adds noise and bot walls (Chromium blocked = site skipped); `expected.json` (5 MB) is edited by every lane: `--update` only your directories, rebase often; new top-level JS state must obey the snapshot purity rules (`NATIVE_API.md` "Load-time purity"); 4 cores are shared with the build.

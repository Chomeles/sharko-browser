# Lane: web-compat (site-compat triage loop, the discovery engine)

> Rules: `docs/RULES.md` wins over anything here; `docs/PROCESS.md` sections 3, 4, 7, 8 define the loop, gates and data model this lane feeds.

Measured 2026-09-29: Linux sweep 07:02 UTC (through the sandbox proxy, `--jobs=3`, settle 3 s, 243 sites), Windows CI sweep 10:08 UTC (six shards, no proxy, 203 sites), master `f4f5daf`; the JS-layer and Rust lanes have merged since, so re-measure before you claim a win. Repro pages, drafts and the Cloudflare MITM kit are in `tools/repros/web-compat/`; the full diagnosis files of the clusters below are in `docs/dossiers/<cluster>/diagnosis.json` (`cf-challenge`, `react-hydration`, `script-errors-mixed`, `page-height`, `bot-walls`, `content-missing-a`, `content-missing-b`, `hidden-content`; paths inside them that point to a scratch directory are historical).

## 1. Mission and owned paths
This lane makes "where is Sharko wrong on the web?" a number instead of an anecdote and keeps the other lanes fed: it runs the sweeps, throws out artefacts of the tool and of the environment, clusters what is left by root cause, writes the diagnosis (minimal repro against Chromium, `--eval` probes, ordered API trace), files it in `docs/compat/`, hands each cause to the lane that owns the code and re-measures after every merge. It fixes engine bugs only where no other lane owns the file (small JS-layer or netstack items, always with a repro); big causes go to the owner lane with a dossier. Windows CI is authoritative (PROCESS principle 4); Linux runs only rank work.
Owned: `tools/sitediff/` (`run.js`, `probe.js`, `gate.js`, `merge.js`, `sites.txt`, new `cluster.js`, `flows.json`, `diff-runs.js`), `tools/repros/web-compat/`, `docs/compat/` (`ISSUES.md`, `issues/*.json`, `history/*.json`, `HISTORY.md`, `BOT-WALLS.md`), `docs/dossiers/`, `tools/gate/thresholds.json` (once it exists; only ever ratcheted down), the sitediff steps of `.github/workflows/windows-smoke.yml` (ask the lead before changing the workflow: it costs Windows minutes). Not yours: TLS/HTTP2 fingerprint and headers (network-security), shadow DOM and cross-realm moves (shadow-components), iframe/document.write/Intl/currentScript (dom-events), fetch/CORS/`cookieStore`/service-worker API surface (web-apis), layout/CSS (layout-css), WebGL/Audio/media (graphics-media); running elsewhere, do not duplicate: css-prefs (alt text, media features), base href, Chrome-identical headers, container queries, layout investigation (airbnb, coursera, bing, pons), kleinanzeigen.

## 4. How to work
- Build: Rust stable, `clang lld libfontconfig1-dev`; `tools/dev-setup.sh` automates the machine once merged. `cargo build --profile profiling -p browser-core -p browser-launcher` (long on a fresh machine: V8, Stylo; `-j N`); binary `target/profiling/browser`. One `target/` only (~8 GB free per machine, no copies). JS-layer edits are embedded at build time: rebuild before running the binary. Item 1-5 and 7 need no Rust build at all: `node` and Playwright are enough (`npm i -g playwright && npx playwright install chromium`; the tools `require('playwright')`).
- Compare: `node tools/sitediff/run.js URL...` (or `--filter=REGEX`, `--random=40 --seed=7`, `--shard=I/N`, `--dark`, `--compare-only`, `--refresh`, `--browser=`), reads `out/report.md`, `out/summary.json`, `out/<slug>/{chromium,sharko}.json|png`, `sharko.log`, `diff.json`. Merge shards with `node tools/sitediff/merge.js merged.json shard*/summary.json`, gate with `node tools/sitediff/gate.js merged.json [--median=8 --max-bad=0.05]`. Chromium results are cached (`--refresh` re-runs them).
- One site by hand: `target/profiling/browser --headless --console --settle=3000 --eval='JSON.stringify(...)' URL` and `node tools/repros/web-compat/chrome.js URL --console --eval=... [--headers] [--screenshot=f.png]` (Sharko's UA, 1280x800); local repros: `sh tools/repros/web-compat/run.sh NAME` (serves the folder on 127.0.0.1:8765, prints the `document.title` JSON of both engines; `NO_PROXY=127.0.0.1,localhost` is set for you; Playwright needs `PLAYWRIGHT_DISABLE_FORCED_CHROMIUM_PROXIED_LOOPBACK=1` in the sandbox). `tools/repros/web-compat/echo-server.js` prints raw request headers of both engines.

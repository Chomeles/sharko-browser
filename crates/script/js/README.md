# JS DOM / Web-API layer

This is the web platform in plain JavaScript, built on the hidden `__native` object (`N`), which
works on the Rust DOM through numeric node ids. `NATIVE_API.md` is the contract. Read its section
"Additions (requested by JS layer)" for the optional natives, the extra hooks, the default-action
split (onEvent flag `4`) and the load-time purity rules that the startup snapshot needs.

Rust runs these files as classic ES2022 scripts, in this order, once per context:

| file | contents |
|---|---|
| `00_prelude.js` | Captures `N` and deletes `__native`. Defines the shared registry `L` (passed on through `__layer`), wrapper stamping (private fields on node wrappers), DOMException, IDL conversions, the microtask helper and internal timers. |
| `10_events.js` | Event and all its subclasses, EventTarget, the dispatch algorithm (capture/target/bubble plus activation behaviour), inline `on*` handlers with legacy scope, AbortController/AbortSignal. |
| `20_dom.js` | Node, Document, Element, CharacterData, Attr, the fragment types (DocumentFragment, ShadowRoot approximation) and collections (NodeList, HTMLCollection). Also the central mutation paths, which feed MutationObserver, custom element reactions and script insertion. Plus the custom element registry, CSSStyleDeclaration/CSSOM, selectors, TreeWalker/NodeIterator, Range/Selection, geometry (DOMRect, DOMMatrix), DOMParser/XMLSerializer and DOMImplementation. |
| `25_xpath.js` | XPath 1.0 through the DOM Level 3 XPath API: `document.evaluate`, `createExpression`, `createNSResolver`, `XPathEvaluator`, `XPathExpression`, `XPathResult`. A parser and compiler to closures over the tree natives (no natives of its own). |
| `30_html.js` | HTML/SVG/MathML element classes with IDL attribute reflection. Forms: validation, submission, reset, FormData sources, select/option. Also activation behaviour (checkbox/radio/label/submit/summary), focus, innerText, template, images, media/canvas stubs, dialog, details and tables. |
| `33_glsl_front.js`, `34_glsl_gen.js`, `35_glsl_rt.js` | GLSL ES 1.00/3.00 for WebGL: preprocessor, lexer and parser; type checker and code generator (shaders become JavaScript functions); runtime library (vector/matrix operators, built-in functions). Error messages imitate ANGLE's info log. |
| `36_webgl.js` … `3c_webgl_ctx.js` | WebGL 1/2 (`WebGLRenderingContext`, `WebGL2RenderingContext`, the object classes, extensions). `36` limits, texture formats and objects; `37` state, buffers, vertex arrays, shaders, programs, uniforms, `getParameter`; `38` textures, uploads, mipmaps, samplers, pixel packing; `39` renderbuffers, framebuffers, clear, draw calls, `readPixels`, queries, sync, the drawing buffer and its presentation; `3a_glraster.js` the software pipeline (vertex fetch, clipping, rasterization on a 1/256 pixel grid with the top-left rule, perspective-correct varyings, stencil/depth/blend); `3b_gltex_sample.js` texture sampling, shadow comparison and derivatives (probe invocations); `3b_webgl2_misc.js` indexed bindings, uniform blocks and transform feedback entry points (not implemented, limits are 0), `3b_webgl_order.js` Blink's property order, `3c_webgl_ctx.js` extensions, context loss and the classes. |

| `40_webapi.js` | Timers, rAF and idle callbacks, MessageChannel/BroadcastChannel, URL/URLSearchParams, the encodings, Blob/File/FileReader/FormData, streams. Networking: Headers/Request/Response/fetch, XHR. Also crypto, performance, console, navigator, `window.chrome`, screen, Location/History, storage, matchMedia, the Intersection/Resize/Performance observers, CSS/FontFace and DataTransfer. |
| `45_indexeddb.js` | IndexedDB: IDBFactory, IDBDatabase, IDBObjectStore, IDBIndex, IDBTransaction, IDBRequest, IDBCursor, IDBKeyRange, IDBVersionChangeEvent. Databases live in memory behind a small storage backend (`L.idbBackend`). |
| `90_bootstrap.js` | The Window object and globals, error reporting, the script execution model (parser-blocking, defer, async, module, dynamic scripts, `document.write`), `onEvent` and the other hooks, final hardening (WebIDL-like property attributes, `[native code]`). It deletes `__layer` at the end. |

The page cannot see `__native`, `__layer` or any internal helper.

## Tests

```sh
node js/test/run.js              # everything (≈5 s); from any directory
node js/test/run.js react        # only files/tests whose name matches /react/i
VERBOSE=1 node js/test/run.js    # also print the page's console output
```

`test/mock_native.js` is a complete `__native` written in JS:
- parse5 for parsing, css-select for selectors, a small cascade for `<style>`/inline styles, fake geometry
- a fake clock with timers, frames and routed fetch responses, plus storage, cookies and history

It follows the Rust semantics: template contents live in content fragments, select state is kept per option, doctypes are dropped, and N.focus can dispatch focus events. Options switch to other native behaviours, e.g. `legacyTemplates`, `noTemplateSupport`, `nativeFocusEvents`, `keepDoctype`, `disable: [...]`, `userAgent`, `noReducedMotion` (an engine without that media feature). To run the whole suite with extra options, set `MOCK_OPTS='{"nativeFocusEvents":true}'`.

`test/harness.js` gives each test a fresh `node:vm` context and a fake event loop (`env.flush()`). With `checkSnapshot` it also checks load-time purity.

Coverage:
- DOM core and HTML semantics, MutationObserver, custom elements (including customized built-ins), forms and validation
- XPath 1.0 (`71_xpath`): the grammar, axes, functions, number formatting, HTML and XML name matching, resolvers, result types and iterator invalidation; many cases are the WPT `domxpath` tests
- the script execution model, event dispatch and activation, timers, microtasks and messaging, cross-origin window stand-ins (`45_ports`: several documents of a page as separate realms, messages between them routed by the mock like the host does)
- networking, URL, encoding, storage, history, observers
- IndexedDB: keys and key paths, ranges, stores, indexes, cursors, transaction lifetime and scheduling, versioning, events and the idb/idb-keyval usage patterns (`70_indexeddb`)
- the Rust integration points (`70_integration`) and guards against quadratic hot paths (`80_perf`)
- the environment as bot-management scripts probe it (`61_chrome_consistency`): `window.chrome`, `Notification`/permissions, Navigator order and secure-context members, `mediaDevices`, the `userAgentData` brand list, `matchMedia` features, about:blank/srcdoc frames
- smoke tests with real libraries: React 19 (production and development builds, bundled with esbuild), Preact + hooks, Vue 3 (global build with the template compiler), and jQuery 3 including `$.ajax`, `$.getJSON` and `$.getScript`

## Chrome consistency

The User-Agent says Chrome on Windows, and pages (bot management, fingerprinting, feature detection) compare the environment with that claim. The layer therefore follows Chromium where a page can see the difference, and stays honest where the engine has no such feature: a missing API is absent, not faked (there is no `AudioContext`, `RTCPeerConnection`, `serviceWorker`, `credentials`, ...). Values were measured in Chromium; `test/tests/61_chrome_consistency.test.js` holds them.

- **`window.chrome`** is a writable, non-configurable data property holding `loadTimes()`, `csi()` and `app` (`isInstalled: false`, `getDetails()` `null`, `getIsInstalled()` `false`, `runningState()` `'cannot_run'`, `installState(cb)` calls back `'not_installed'`, `InstallState`, `RunningState`), and no `runtime` (a page without extension access has none). `loadTimes`/`csi` are anonymous constructor functions and print as `function () { [native code] }`, the `app` functions as `function getDetails() { [native code] }`. Their times come from the same milestones as `performance.timing`.
- **`Notification.permission`** is `default` in a secure context and `denied` in an insecure one (Chrome); `requestPermission()` resolves `denied` without changing it (there is no prompt) and rejects a non-function argument. `permissions.query({name:'notifications'})` agrees (`prompt`/`denied`). Other permissions answer like Chrome with no grants (`granted` for accelerometer, gyroscope, background-sync, clipboard-write, screen-wake-lock, ...; `prompt` for camera, microphone, geolocation, ...; everything `denied` when insecure) and reject bad descriptors with Chrome's messages.
- **Secure contexts.** `Navigator`'s `[SecureContext]` members (`clipboard`, `mediaDevices`, `storage`, `deviceMemory`, `userAgentData`, `locks`, `getBattery`, `getUserMedia`) and the `MediaDevices` interface do not exist in an insecure document (plain http). The layer is snapshotted before the URL is known, so `onDocumentParsed` removes them, before any page script runs. `L.isSecureContext()` is the single source (`window.isSecureContext`, `crypto.subtle`, permissions, Notification).
- **`Navigator.prototype`** lists its members in Blink's order (`vendorSub, productSub, vendor, maxTouchPoints, ..., vibrate, constructor, clipboard, mediaDevices, ...`; scripts hash it), without the members the engine does not have and without Firefox's `oscpu`. In general the bootstrap moves `constructor` behind the members of every interface (as V8 installs it) and makes static members enumerable (WebIDL); `L.orderKeys(proto, keys)` sets an explicit order (Navigator, Notification, NetworkInformation, PermissionStatus, MediaDevices). Not done: Blink's alphabetical order of operations within an interface.
- **`navigator.mediaDevices`** is a device-less `MediaDevices`: `enumerateDevices()` resolves `[]`, `getUserMedia()` rejects `NotFoundError: Requested device not found` (`TypeError` when neither audio nor video is asked for), `getDisplayMedia()` rejects `NotAllowedError`; the legacy `navigator.getUserMedia`/`webkitGetUserMedia(constraints, ok, err)` call `err` with the same error. `getSupportedConstraints()` lists the constraints Chrome knows.
- **`navigator.userAgentData`** builds its brand list like Chromium (`GenerateBrandVersionList`): the GREASE brand (`Not=A?Brand`/24 for Chrome 140) and the order of the three brands follow from the major version of the User-Agent; `getHighEntropyValues()` reports a full version (`140.0.7339.207`) instead of `140.0.0.0`.
- **`matchMedia`** asks the style engine, which knows only Stylo's Servo features. The layer answers the others like Chrome on a desktop screen: `color-gamut` (srgb), `display-mode` (browser), `dynamic-range` (standard), `forced-colors` (none), `prefers-contrast`/`-reduced-motion`/`-reduced-transparency` (no-preference), `scripting` (enabled), `update` (fast), `overflow-block`/`-inline` (scroll), `color` (8), `color-index`, `monochrome`, `grid` (0), including `min-`/`max-` and range syntax, by replacing such conditions with a constant one before asking (see `NATIVE_API.md`). A feature the engine answers itself (say `prefers-reduced-motion` once it is wired up) is left to it. `MediaQueryList.media` is the canonical form (`(min-width: 600px)`, `screen, print`). Stylesheet `@media` rules are evaluated natively, so they still do not see these features.
- **about:blank and srcdoc frames.** The host gives the initial `about:blank` document of an `<iframe>` (no `src`, `src="about:blank"` or a `javascript:` URL) and a `srcdoc` document the parent's URL (their origin, secure-context state, cookies and referrer are inherited from there, which is right). The layer recognizes them from `N.frameElement()` (attributes `srcdoc`/`src` in the parent, and that its own URL is the parent's), pinned when the document is parsed, and shows what Chrome shows: `location.href`, `document.URL` and `documentURI` are `about:blank` (`about:srcdoc`), `location.origin` is `'null'` (but `window.origin` is the inherited one), `baseURI` is the parent's base URL (also for relative references), `compatMode` is `BackCompat` and `readyState` is `complete` at once. `document.open()` (or a `write()` after parsing) hands the document the URL of its opener, as in Chrome. `L.documentURL()` stays the host's URL for everything internal (origin checks, storage keys, resolving); `L.exposedURL()` is what the page sees. A frame that was navigated without touching its `src` (link or form with `target`) has a URL of its own and is not affected. Deviation: a `srcdoc` document loads asynchronously in Chrome (it is `about:blank` for a moment).

Needs the host, not done here: `Intl`'s default locale still follows the process locale (`Intl.DateTimeFormat().resolvedOptions().locale` is `en-US` while `navigator.language` is `de-DE`; `v8::icu::set_default_locale` before the isolates are created fixes it), `typeof document.all === 'undefined'` (needs an undetectable object), and the `Sec-CH-UA*` request headers that go with `userAgentData`.

## Known gaps / deviations

- **Shadow DOM is an approximation.** The shadow content is rendered as the host's children and slotted light nodes are moved into their `<slot>`. The host's light-DOM getters therefore see the composed tree. Stylesheets inside a shadow root are scoped to its host natively (`N.setShadowHost`: selectors are prefixed with the host, `:host`/`:host()`/`:host-context()`/`::slotted()` are rewritten), which keeps component styles from leaking into the page; outer styles still reach into the shadow content. Declarative shadow roots (`<template shadowrootmode>`) are attached when the document is parsed. There is no event retargeting, and closed mode only hides `shadowRoot`.
- **No wrapper GC.** Wrappers are cached by node id for the page's lifetime, because expandos and identity must survive. So `N.releaseNode` is never called, and nodes that were ever wrapped stay alive.
- **MutationObserver, custom element reactions and Range only see mutations made through the JS DOM API.** Native changes do not produce records: parser output, user text editing, and Rust-side details toggles or form resets. Ranges are not live: boundary points are not adjusted on mutation.
- **`document.write` is an approximation.** Written markup is parsed as a fragment and inserted after the current parser-inserted script, with an open-element stack for split tags. After load it replaces the body content. Script-created `document.open()` is not a full reset. The scripts of written markup are queued like parser-inserted ones in all paths (during parsing, after load, nested in a written script): only their execution is sequenced, the markup itself is in the tree at once.
- **Unsupported, or stubbed as absent or `null`:** import maps (`<script type=importmap>` is ignored), iframes and nested browsing contexts (`contentWindow` is `null` in the unit-test harness; the browser runs each frame in its own realm, see `crates/script/src/lib.rs`), SharedWorker, module workers, EventSource, WebGL, WebAssembly streaming helpers, `OffscreenCanvas`, CacheStorage (`caches`). Canvas 2D and media elements are inert stubs. `Notification` exists but is never granted.
- **IndexedDB is in memory.** Databases do not survive a page load and are not shared between the frames of one origin (each frame's realm has its own layer). The engine (transactions, scheduling, key generators, indexes, cursors, versioning) follows the spec; only `L.idbBackend` (`databases`, `commit`, `drop`) would need a persistent implementation. Not implemented: Blob/File values nested in a stored value (`L.cloneValue` only passes a top-level Blob through), forced connection closes (`close` event). A transaction is deactivated by a timer after its last event, not by the end of the microtask checkpoint, so code that runs from an earlier-registered `setTimeout(0)` in the same task may still see it active.
- **Frame windows without a realm are Proxy stand-ins.** In the browser each frame has its own realm (see `crates/script/src/lib.rs`), and `contentWindow`/`parent`/`top` are that realm's real `window` if it is same-origin (`N.realmGlobal`). Any other frame window (another origin, or not loaded yet; every one in the unit-test harness) is a stand-in that only reaches the frame through `N.framePost`. A cross-origin one follows the HTML "cross-origin objects" rules: only the CrossOriginProperties and the child frames are visible (spec descriptors, `then`/symbol fallback, null prototype), everything else is a SecurityError, and its `location` is a Location with a write-only `href` that navigates through the optional `N.frameNavigate`. Each property is one function per stand-in, created in the realm that reads it, and acts on its `this` like a `[Global]` operation: `null`/`undefined` is the calling window (so `const post = parent.postMessage; post(msg, '*')` posts to the caller, as in browsers), any other non-window is an `Illegal invocation`. Deviations: a real window's own `postMessage` ignores `this`; `opener` is always `null` and `closed` always `false`. A same-origin child without a realm yet gets a lenient stand-in (expandos, `document` is `null`, listeners that never fire).
- **Transferring ports and buffers.** MessagePorts and ArrayBuffers in a `transfer` list move between the documents of a page (`window.postMessage`, `port.postMessage`, `frame.contentWindow`, `parent`, `event.source`), also nested and inside the message (as a property, array element or Map value, not in a Set or as a Map key); other transferables are ignored. A channel whose ports left runs through the realm that created it (see "Ports across frames" in `NATIVE_API.md`) and ends with that document. Inside one realm the port object itself is delivered rather than a new one. `close` events, `Worker`/`SharedWorker` ports and `structuredClone(x, { transfer })` are not implemented. An ArrayBuffer is copied and then detached, not moved.
- **Dedicated workers run on the page's thread.** Each `Worker` has its own realm (globals, `importScripts`, `self`, timers, messages), but long-running worker code blocks the page, and `Atomics.wait` is unavailable.
- **`window.open`** returns `null`, even when `N.openWindow` opens a tab. `alert`/`confirm`/`prompt` only log, returning `undefined`/`false`/`null`.
- **The DOMParser XML parser is a small JS parser**: predefined and numeric entities only, no DTDs. XSLT is not implemented.
- **XPath is XPath 1.0 as the browsers ship it, with these limits.** The namespace axis is empty, and a variable reference is an unbound variable that evaluates to the empty string, as in Blink (Firefox throws). Trees inside emulated shadow roots are part of the document tree (see Shadow DOM above), so `//x` from a shadow tree also finds the page's nodes. Attribute namespaces are recovered from the `xmlns:` declarations in scope (plus `xml`, `xmlns` and `xlink`), because attributes only keep their qualified name, so `setAttributeNS` with an undeclared namespace is not matched by `@p:name`. On HTML elements of HTML documents `xmlns`, `xml:lang` and `xlink:href` are plain attributes, as the HTML parser makes them (only SVG and MathML elements get namespaced ones), so `lang()` ignores an HTML element's `xml:lang`. `following::` from an attribute starts after its element's subtree, as in Blink and libxml2 (XPath 1.0 would also count the element's children). An iterator turns invalid (`InvalidStateError`) on child-list and attribute changes, not on text edits. The optional `result` argument of `evaluate` is accepted but a new `XPathResult` is always returned, like Chromium. Numbers convert to strings without an exponent (`string(1e21)` is `1000000000000000000000`, as XPath 1.0 asks; Blink prints `1e+21`).
- **Named properties of `Document`** (`document.loginForm` for forms, images, embeds, objects and iframes) never replace a real property, unlike the specification's `[LegacyOverrideBuiltIns]` (`<img name=body>` would clobber `document.body`, and the layer reads `document.*` itself). The lookup lives in a proxy between `Document.prototype` and `Node.prototype` (so `Object.getPrototypeOf(Document.prototype)` is not `Node.prototype`); `in` has no receiver and answers for the main document.
- **Text tracks are model only.** `<track>.track`, `media.textTracks`, `addTextTrack()`, `TextTrack`, `TextTrackCue`/`VTTCue`, `TextTrackCueList` and the `addtrack`/`removetrack`/`change` events work and follow the child `<track>` elements, but a track's `src` is never fetched (readiness stays `NONE`, no `load`/`error` event, no automatic selection of a `default` track), no cue ever becomes active (no `cuechange`/`enter`/`exit`), and there is no `VTTRegion` (`VTTCue.region`) or WebVTT parser (`getCueAsHTML()` only strips tags).
- **`innerText` reads computed style element by element**, so it is correct but slow on very large subtrees.
- **The JS-only template fallback** (a native without `N.templateContent`) cannot make native serialization see template contents.

## WebGL

`canvas.getContext('webgl' | 'experimental-webgl' | 'webgl2')` returns a real context that draws with a software pipeline in JavaScript (`33`–`3c`). What it reports is what it does:
- **Identity and limits** follow Chromium 140: the ANGLE/SwiftShader profile (`Google Inc. (Google)`, `ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device (Subzero) …`; limits as measured in Chromium without a GPU, see `PROFILE_SWIFTSHADER` in `36_webgl.js`) because nothing but this pipeline renders, and the ANGLE/D3D11 profile when the host answers the optional native `N.gpuAdapterInfo()` with a GPU adapter. Own property names, their order, `length`s and constants are Chromium's (`test/webgl_golden.js` records answers of Chromium; `test/tests/62_webgl.test.js` compares pixels, errors and reflection).
- **Not implemented, therefore not reported:** multisampling (`antialias` is `false`, `SAMPLES`/`MAX_SAMPLES` 0), compressed texture formats, line widths other than 1, anisotropic filtering, timer queries, uniform buffer objects and transform feedback (their limits are 0 and the entry points fail with the spec's errors), `EXT_shader_texture_lod`. `mediump`/`lowp` run in the same precision as `highp` (`getShaderPrecisionFormat` says so).
- **Presentation:** the drawing buffer is copied into the canvas surface at the end of the task (and synchronously by `toDataURL`, `drawImage`, `texImage2D` of the canvas); without `preserveDrawingBuffer` it is cleared afterwards, but the canvas keeps showing the frame (Chromium would encode the cleared buffer from `toDataURL` after the frame).
- Derivatives and automatic texture LOD come from probe invocations of the fragment shader at the neighbouring pixels (the call sequence of the primary and the probe runs pairs the values), so shaders whose derivative-consuming calls diverge between pixels see zero derivatives.
